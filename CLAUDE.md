# CLAUDE.md

Research repo: semantic / task-oriented communication for battery-free (WISP) camera person detection. See `README.md` for the project goals and layout.

Keep training code device-agnostic (`cuda` if available, else `cpu`) and runnable as a script with paths and configs passed in, so it can move to the cluster.

  `cd data_exploration && ../.venv/Scripts/jupyter.exe nbconvert --to notebook --execute --inplace <nb>.ipynb`

## Data conventions (PIROPO Room B, conventional camera)

- Root: `data/roomb_piropo/Room B/conv_2B/conv_2B/` (note the space in `Room B` and the doubled `conv_2B`).
- Sequence folders `conv2B_<name>`; annotations `Ground_Truth_Annotations/groundTruth_conv2B_<name>.csv` exist only for `training`, `training_seats`, `test1`, `test2`, `test3`.
- CSV row `i` (1-based) is the i-th JPEG in **sorted file-name order** (file names are timestamps). Columns: `frame, x1, y1[, x2, y2]`, one head point per person in 704×576 pixels; `(0, 0)` means an empty slot. `test2` has up to 2 people, the rest at most 1. A few points have negative x (person partly out of frame).
- About 43 corrupted frames (block-shifted JPEGs) are labelled 0 regardless of content. Flag them by mean gray level more than 15 from the sequence median, and exclude them. The mean-level flag misses some: about 10 frames in the annotated sequences have their lower part filled with one gray level (many rows with std < 2) and are not flagged, and mildly darkened frames slip under the 15-level threshold.
- Annotations miss people: about 8% of empty-labelled `training` frames (1% in `training_seats`) get a COCO-detector person score of 0.9 or higher and show visible people. Treat measured AUC as capped by label noise; full-resolution detector scores (`results/coco_detectors/`) can serve as pseudo-labels.
- Split by sequence or by contiguous time block. Adjacent frames are near-duplicates.
- `training_bg` = empty room; the layout differs in `training_seats`, so a fixed background does not transfer. It is also about 25 gray levels off from the empty frames of every annotated sequence (lighting), so take an empty-room reference from the sequence itself.

## Mall dataset

- `data/mall_dataset/mall_dataset/frames/seq_%06d.jpg` (1-based), 640×480; `mall_gt.mat` head points are only annotated inside the ROI (`perspective_roi.mat`), so the top-corner shop fronts hold unannotated people and mannequins.
- Presence data comes from tiles: `data/mall_dataset/cropped/labels_<grid>.csv` with label 1 / 0 / -1 (ambiguous: a body reaches in without its head, or the tile is outside the ROI). Use only 0 and 1.

## Conventions shared with the Colab experiments

- WISP input: grayscale **160×120** (`H, W = 120, 160`), bilinear resize from native resolution.
- Payload budgets in bytes at 8 bits per value: 10, 40, 160, 640, 2560 (roughly 1 EPC up to many). Thumbnail grids must divide 160×120 exactly (4×3, 8×6, 16×12, 32×24, 40×30, 80×60).
- Prefer threshold-free metrics (AUC) or per-sequence results: the labelled sequences are 55–80% positive.

## Code layout

- `semwisp/` holds shared helpers (`piropo.py`: `load_sequences`, `load_gray`, `flag_bad`, `thumb`, `auc`; `mall.py`: Mall dataset `load_gt`, `load_roi`, `grid_boxes`, `crop_labels`). New code should import from here rather than copy notebook code. The exploration notebook predates it and still has its own copies.
- WISP simulator (`semwisp/sim.py`): `replay(seqs, tag, server, link, sensor)` runs one query per frame in time order. The server sends `Request`s, the tag answers each with real payload bytes, and a `Ledger` counts what the query cost (rounds, downlink bits, payload bytes, EPCs, pixels read, MCU operations, RAM). New methods are a `Tag` subclass in `semwisp/tag/` and/or a `Server` subclass in `semwisp/server/`; tag code is integer-only so it can be ported to C or Verilog. Frames come from `semwisp.frames.load_frames` (cached in `data/cache/`). `semwisp/cost.py` energy constants are unmeasured (`None`): do not report energy until they are filled in. Plumbing tests: `.venv/Scripts/python.exe tests/test_sim.py`.
- Project direction (user, 2026-11-10): the method must adapt online to any room with no offline retraining; the claims to support are that the tag needs only certain pixels, and how long readaptation takes. `OnlineLearner` is the method; `BatchLearner` (store frames, refit) is a baseline.
- Adaptive loop: `semwisp/server/adaptive.py` (`AdaptiveServer(teacher, learner)`, `OnlineLearner`, `BatchLearner`, `CachedTeacher`) with `semwisp/tag/interval.py` (`IntervalCodeTag`: ops `full`, `config`, `code`, `thumb`; candidate-region tables `CELLS`, `sparse(table, sample)`, `lattice(block)`, rows are `x0, y0, w, h, sample`). `semwisp/metrics.py`: `balanced_accuracy`, `summary`, `readaptation`. `semwisp.frames.load_mall_tile()` gives one Mall tile as a second scene (labels 1/0/-1). Run it with `replay(..., reset=False)` so tag and server state persist across sequences. The teacher is the cached COCO detector on 160×120 frames (`results/coco_detectors/frcnn_mnv3_320_160x120_s2.npz`, every 2nd frame of the annotated sequences); it is only about 0.86 balanced-accurate, and PIROPO's sequences are staged scenarios, so first-pass results understate and replayed passes overstate what a real room would give.
- Tiered checks: `semwisp/server/tiered.py` (`TieredServer`, `ThumbDecoder`) checks the code against a 16×12 thumbnail (tag op `thumb`) before fetching a full frame. JPEG baseline: `semwisp.tag.JpegTag` (header not counted; also a `jpeg` method in `thumbnail_sweep.py` and `jpegWxHqQ` conditions in `coco_detector_eval.py`). Every code a run deployed (for pictures): `experiments/code_snapshots.py` replays a `tiered_checks.py` run, checks it reproduces the stored one, and saves the codes to `results/tiered_checks/snapshots/` (kept out of the run folder's top level, which the notebook globs). Detector scores for the Mall tile: `results/coco_detectors/frcnn_mnv3_320_mall_tile_160x120.npz` (`coco_detector_eval.py --mall-tile`). DINO ViT-S/8 weights: `data/cache/weights/dino_vits8_hf.bin` (Hugging Face `facebook/dino-vits8`; `dl.fbaipublicfiles.com` served an expired certificate).
- pandas 3 stores strings with their own dtype, not `object`: when saving a DataFrame to npz, convert non-numeric columns with `np.array(col.tolist(), dtype=str)` or they are pickled.
- Experiments: a resumable script in `experiments/` writes to `results/<experiment>/` (one file per configuration; skip if it exists), and a notebook next to it analyses the cached results. Run scripts from the repo root, e.g. `.venv/Scripts/python.exe experiments/coco_detector_eval.py --help`.
- Notebooks add the repo root to `sys.path` (`sys.path.insert(0, str(Path('..').resolve()))`) to import `semwisp`.

## Teacher screen (2026-11-12, `experiments/teacher_eval.py`, analysis in `teacher_eval.ipynb`)

- Candidate teachers are torchvision COCO detectors given `model@min_size[+flip]`. They score the cached 160×120 gray frames, the same arrays the replays use. Results go to `results/teachers/<teacher>_s<stride>/<sequence>.npz` (`t, idx, score, box`; `mall_tile` with `--mall`). Logs: `results/teachers/screen_s8.log`, `fcos_s2.log`. `--batch` sets frames per forward pass; a sequence in progress is checkpointed to `<sequence>.part.npz` every `--chunk` frames and resumed.
- Screened on every 8th frame of the annotated sequences, with corrupted frames excluded. Done: `frcnn_mnv3_320@320` (the current teacher), `frcnn_mnv3_320@640`, `frcnn_mnv3@800`, `fcos_r50@480`, `retina_r50v2@480`, `kprcnn_r50@480`. Not done: `frcnn_r50v2@480` and `kprcnn_r50@800` (the run was killed for low memory). CPU cost is 0.11 s/frame for the current teacher, 0.8–1.1 for FCOS and RetinaNet, and 1.7 for Keypoint R-CNN.
- The current teacher's errors are one-sided. Its person labels (≥ 0.6) are 2% wrong (0.2% once the annotations' missed people are counted as person). About **32% of its empty labels (≤ 0.3) show a person**: at 160×120 it often gives a visible person 0.2–0.3. A stricter empty cutoff helps (≤ 0.05: 6% wrong, but only 49% of frames get a label).
- Ranking: AUC against corrected labels (`frcnn_mnv3_320_rgb_s2` full-resolution ≥ 0.9 frames also count as person), and the share of frames a teacher can label with ≤ 1% wrong labels, using monotone cutoffs set from the labels (for ranking only):
  - Room A (`training`, `test1`, `test3`): current 0.917 / 65%, FCOS 0.992 / 77%, RetinaNet 0.990 / 69%, Keypoint R-CNN 0.996 / 95%.
  - Room A2 (`training_seats`, `test2`, mostly seated and half-hidden people): current 0.922 / 36%, FCOS 0.959 / 51%, RetinaNet 0.945 / 47%, Keypoint R-CNN 0.906 / 31%.
- **Empty labels are the bottleneck.** At stride 8, A has 140 empty frames and A2 has 122. At ≤ 1% wrong the current teacher labels 1 of A's empty frames and 13 of A2's; FCOS labels 31% / 13% (92% / 13% at ≤ 5% wrong); RetinaNet labels none (89% of A's at ≤ 5%). No teacher labels more than 25% of A2's empty frames at ≤ 5% wrong. FCOS with the loop's 0.6 / 0.3 cutoffs: 0% wrong person labels, 4% (A) / 11% (A2) wrong empty labels; its clean empty cutoff is about 0.21–0.23.
- FCOS stride 2 plus Mall tile is done (`results/teachers/fcos_r50@480_s2/`, 0.9 s/frame). It confirms room A (AUC 0.987, 31% empty recall at ≤ 1% wrong) but A2's clean empty recall falls to **2%** of 487 empty frames (stride 8's 13% was small-sample luck); A2 AUC 0.958 and 10.6% wrong empty labels at 0.3 hold. Room A2 has almost no clean empty labels from any teacher tested.
- **FCOS at 480 is the only candidate better than the current teacher in both rooms.** Keypoint R-CNN is best in A and worst in A2. Upscaling the current model's input (`frcnn_mnv3_320@640`) hurts (AUC 0.860 / 0.846 in A / A2), and `frcnn_mnv3@800` is better (0.967 / 0.935) but gives no clean empty labels in room A.
- Score scales differ by model (FCOS mostly 0.2–0.8), so the loop's fixed cutoffs (`pos_thr=0.6, neg_thr=0.3` in `AdaptiveServer`) don't carry over between teachers.
- Score floor bug (fixed 2026-11-13): FCOS and RetinaNet take `score_thresh`, not `box_score_thresh`, so their results before the fix have floors of 0.2 and 0.05 (scores below are 0). Scores above the floor are unaffected. It matters for RetinaNet's empty-label numbers (150 of 857 stride-8 frames are 0); rescore it before relying on them.

## FCOS as the loop's teacher (2026-11-13)

- Cutoffs without labels: `semwisp.calibrate.asymmetric_cutoffs`, fitted on FCOS's scores of the unannotated sequences (`results/teachers/fcos_r50@480_s4/`): person ≥ 0.613 (two-mode mixture, posterior 0.99), empty ≤ 0.309 (empty mode's left side, peak + 2.33 spread). A plain mixture gave empty ≤ 0.43 (13–19% wrong); people push scores into the gap, so only the empty mode's left side is clean. Label check: person labels 0.3% wrong, empty labels 5% (A), 11% (A2), 1% (Mall tile).
- `tiered_checks.py` has a third teacher, `fcos`; teachers carry their own cutoffs (stored in each run's meta). Results in `tiered_checks.ipynb` section 5. Over the six learner × check configurations, FCOS closes about 40% of the gap between the current teacher and true labels (PIROPO pass 2: 0.862 → 0.894, oracle 0.934). It halves the uplink on pass 2 (1,445 against 3,268 B/query, the same as true labels). *Unsure* full frames fall from 11% to 3% of queries.
- The 96-pixel online learner with tiered checks gains least (0.00–0.01); the teacher is no longer its main limit. On the Mall tile FCOS is no better than the current teacher.
- The current teacher's fast change detection in the rearranged room (14 queries, against 140 with FCOS and 162 with true labels) came from its wrong empty labels on seated people, while the old code was answering correctly. So deploy-query counts depend on the teacher: report accuracy over time after a move alongside them.

## Supervised reference, learner diagnosis, readaptation (2026-11-13)

- Problem framing (user, 2026-11-13): few-shot, task-oriented semantic compression. Place a WISP anywhere with a task, and it should adapt as fast as possible to high compression at similar task performance, across views and objects. Zero-shot for the task (pretrained server teacher), few-shot for the scene (empty references and teacher-labelled frames).
- `experiments/supervised_ceiling.py`: a 96-region code fitted with true labels on a room's own frames, scored on held-out contiguous time blocks (5 blocks, 10-frame gaps); results in `results/supervised_ceiling/<room>_<fitter>_<table>.npz` (per-frame held-out logits). Rooms `A` (training, test3, test1), `A2` (training_seats, test2), `mall`. Batch fit: A 0.77 / 0.82, A2 0.79 / 0.83, Mall 0.96 / 0.96 (pixels / cells). **In PIROPO it is a reference, not a ceiling**: the rooms change within a recording and the loop matches or beats it (e.g. the end of A2, where the fixed code misreads an empty stretch).
- `experiments/learner_ablation.py` (`results/learner_ablation/results.csv`): the online learner's shortfall with all labels is mostly its **decoder** (LDA weights and midpoint threshold), not region selection or interval rule. `OnlineLearner(shrink=0.3, threshold='gauss')` (covariance shrinkage; threshold where the two classes' Gaussians cross, from running per-class covariances) raises Mall cells from 0.885 to 0.95 with all labels. Defaults are unchanged; `tiered_checks.py` runs it as `online_pixels_cal` / `online_cells_cal`. λ = 0.3 was chosen from the ablation table.
- Replays: the calibrated decoder helps with tiered checks (+0.003 to +0.035 in 9 of 10 PIROPO and switch comparisons); with full-frame checks it is mixed. On the Mall tile, from query 1,000 on, the 96-pixel tiered learner sends 970–1,216 B/query instead of 5,575–9,801 and is closer to the reference. In room A it is more accurate but checks more often (FCOS: 1,629 against 115 B/query after query 1,000).
- `experiments/readaptation.ipynb`: gap to the reference and bytes per query by time since each move (0–99, 100–299, 300–999, 1,000+ queries), same frames. FCOS + calibrated 96-pixel tiered learner: within about 0.05 of the reference 300–1,000 queries after a move, at 1–4 kB/query; steady state is still about 100× the 12-byte code (checks dominate). A single recovery time (first window within 0.05 and ≤ 2 kB/query) is fragile: 50–1,700 queries, and later windows often fall out again.

Adaptive (same detector, `online_pixels_cal` tiered, 2nd pass) 0.863 @ 2,018. So against good JPEG the adaptive advantage is about 3×, not 10×; the detector is not tuned for compressed input.

Second half of each room: 235–510 B/query (pixels). So the loop is ~4× below non-adaptive JPEG q88 (5,034 B) over a first pass, ~10–20× once settled, but still ~0.04 below its accuracy (0.921).

## Long static-room test (2026-11-13, `experiments/static_room.py`, `static_room.ipynb`)

- One room replayed 6× with state kept; `online_pixels_cal`, tiered checks; FCOS and true labels; schedules `default` (max_interval 64, full_every 4), `relaxed` (1024, 16), `floor` (relaxed + `noise_floor=0.05`). Results in `results/static_room/`. FCOS on every full frame, same frames: room A 0.910, Mall 0.956 at 19,200 B.
- **Room A converges; the check schedule set the floor.** Relaxed, FCOS: 0.890 at 101 B/query from pass 4 (190× less than a full frame; = 12 B code + 20% thumbnails + 0.3% full frames). Default, FCOS: 0.929 at 221 B by pass 6 (above full-frame FCOS); true labels 0.962 at 347 B. Identical frames each pass, so best case.
- **Mall tile stalls at ~850–1,000 B/query** for every schedule: nearly all its full frames are anomaly-triggered (see step 1).
- **`noise_floor` is unstable with a noisy teacher** (room A, FCOS: 5 spurious change resets, 0.80–0.90 at 0.4–3.2 kB). Kept as an option (default 0), not recommended.

## Compression as prediction (2026-11-17, `experiments/cumulative_bits.ipynb`)

- Framing (user, 2026-11-17): compression = prediction; the server should predict what the tag will say, keep state over time, and pay only for surprise. The loop is a universal code: report readaptation as the **excess bits over the settled rate after a move** (the learning cost), and cumulative uplink against non-adaptive lines.
- Switch stream, JPEG full frames: cumulative uplink below JPEG q88's from query 244 on; learning a room costs 0.7–2.4 MB = 230–360 JPEG q88 frames, 90% paid within 320–750 queries.
- `semwisp.server.TemporalServer` (`semwisp/server/temporal.py`; `static_room.py` schedules `relaxed_temporal`, `relaxed_smooth`, `relaxed_anomaly`; `tiered_checks.py` check `temporal`): an HMM belief (change rate learned per room from teacher-label pairs) decides answers and uncertain-answer thumbnails; the anomaly trigger is mean + 4 sd of the share of set bits for each class (`frac_stats` that `OnlineLearner.make()` now attaches to the decoder, with `out_stats`); a one-query anomaly is answered but not learned from (`hold_glitches`).
- Static room, last pass, against `relaxed`: Mall 0.938 at 75 B/query (was 0.909 at 944; the drift is gone), room A 0.906 at 57 B (was 0.890 at 101). Mostly from the learned anomaly trigger; the belief alone doesn't help (room A locked in a weak code, 0.765).
- **Worse across moves**: switch stream 0.834–0.837 against 0.882–0.884 (FCOS, JPEG full frames). The trigger learned in the Mall is too high to catch the next move (detected at query 497 instead of 140). Next: surprise as −log p(bits | class) under the learner's per-bit rates, scored against its own running distribution, persistent over queries.
- Comparison against the other servers and non-adaptive tags in a settled room: `experiments/temporal_compare.ipynb` (pass-by-pass, accuracy vs bytes, byte breakdown, close-up). Videos: `experiments/temporal_video.py` replays two `static_room.py` runs (checked against the stored ones) and renders camera | tiered | temporal side by side → `results/demo/temporal_<room>_p<pass>_<start>-<stop>.mp4` (+ a still `.png`).
- Framing (user, 2026-11-17): realistic deployments stay in one room (people come and go, furniture moves); moving the tag to a different room is not the main case, so the switch-stream weakness is secondary.
- A corrupted frame the mean-level flag misses sits in room A's stream (test1, every-2nd-frame index 74); every replay fetches it as an anomaly.

## Next steps

1. **HIGH PRIORITY: per-room anomaly trigger and code margin** (2026-11-17: a learned bit-share trigger fixes the Mall stall but hides moves; see "Compression as prediction") (follow-up of the static-room test above). The Mall tile stalls at ~850–1,000 B/query because the anomaly trigger (> 40% of code bits set → full frame) fires on ordinary person events there (77–129 times per pass, against 2–3 in room A). Learn the threshold per room (e.g. above the share of bits a person usually sets, from running statistics), and calibrate the uncertain-answer thumbnails (|logit| < 2, 20–27% of queries, ~40–50 B/query). Rerun `static_room.py` (new schedule name) and the switch stream. Also find why Mall accuracy drifts down over identical passes (0.935 → 0.905, true labels too).
2. Steady-state cost in changing rooms: which checks are needed (the calibrated decoder triggers many *unsure* / *disagree* checks in room A); e.g. let a confident thumbnail supervise the code. Compare with the JPEG/thumbnail baselines at the same accuracy.
3. A first new-object test (the "different objects" half of the framing): the same loop with a different COCO class as the teacher's query, on footage we have (e.g. chairs in `training_seats`), or a dataset with several object types.
4. More views/rooms for "any area": check what other PIROPO rooms and cameras are on disk.
5. A bound test for the pixel-prior idea (no new models). Use the head-annotation density as a perfect "where can a person appear" prior, combine it with per-pixel noise from a few empty frames, and build a no-label 96-pixel code. Near the label-using best code's 0.95 means an affordance prior (depth and floor/seat segmentation, or generative insertion of the object into the empty frame) is worth building. Near the uniform lattice (0.81–0.88) means it isn't. Attention maps fit queries about objects already in the frame (door open, seat occupied) better than "where will X appear".
6. Optional: finish `frcnn_r50v2@480` and `kprcnn_r50@800`, and rescore `retina_r50v2@480` with the fixed floor (same command, resumes; small batch; move the old folder aside first).
